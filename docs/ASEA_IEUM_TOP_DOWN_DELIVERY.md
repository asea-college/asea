# 아세아 이음 — 탑다운 통합 완성 우선 개발 지침 (2026-10-31)

## 최우선 사용자 승인 원칙
- 사용자는 **기능별 알파/베타 APK를 순차적으로 열어 보고 승인하는 방식이 아니라**, 지금까지 확정된 모든 요구사항을 전체 시스템에 통합한 **동작 가능한 완성형 통합 검증판**을 먼저 검토하고, 그 후 변경 사항을 지시하는 탑다운 개발 방식을 선택하였다.
- 개발자는 단순 로그인만 가능한 APK, 버튼이 장식인 APK, 구현되지 않은 메뉴를 '완성' 또는 '통합 검증판'이라고 제공하지 않는다.
- 단계는 내부 구현·테스트를 위한 것이며 사용자에게 각 단계마다 사양 승인을 요구하지 않는다.
- 새 요구사항은 먼저 전체 기능 목록·서버 규칙·화면 흐름·플랫폼별 영향에 일괄 반영한다.
- 통합 검증판의 완성 기준은 각 주요 기능을 실제 계정 간 E2E로 검증하고, 실패하는 기능에 대하여 원인을 수정·재검증한 상태이다.
- 시간·비용·접근 권한·빌드 환경 제한으로 전체 완료가 불가능하면 완료된 부분과 불가능한 이유를 정확히 보고하되, 부분 결과를 '요청하신 전체 완성판'으로 오인시키지 않는다.

## 통합 개발 완료 범위
1. 계정: 교직원 가입(15개 부서 선택), 관리자 승인, 정상 로그인·비밀번호 복구, 마스터/일반/부서별 역할과 서버 권한.
2. 채팅: 전체·부서·1:1, 대화 개설·상대 검색·메시지 발송/수신·시간순 누적·과거 업무기록, 읽음·알림·검색·첨부.
3. 조직/관리: 부서명 변경·재배치·신규 부서 자동 연결·기존 부서 유지·조용히 나가기·인수인계·권한 이력.
4. 공지: 공식 공지·확인 응답·관리자 집계·기록보존.
5. 투표/일정: 익명·실명, 단일·복수, 마감·결과, 후보 날짜·시간 조율·일정 확정.
6. 소통: 마니또·익명 감사·커피 메이트·선한 행동·부서 릴레이·가위바위보·점심 추첨·팀 나누기·퀴즈·칭찬/사연.
7. 방송: 이음 방송국 편성·DJ·검토 사연·합법적으로 이용할 권리가 있는 오디오 송출·기기 재생 동의.
8. 플랫폼: Windows PC 앱, 웹앱, Android 설치 APK, iOS 앱 준비/검증, Supabase 공유 계정과 데이터 동기화.
9. 보안: 외부 계정 간 자료 누출·익명 신원 누출 방지, 서버 RLS/RPC, 서명 유지, 비밀번호·비밀키 보호.
10. 품질: 모든 표시 버튼이 기능/내비게이션과 연결, 빈 상태·오류 상태 안내, 다운로드와 설치 검증, 실기기 E2E, 자동 회귀 테스트.

## 내부 작업 및 출시 게이트
- 기능 개발은 계층별 병렬 작업(데이터·API/권한·UI·플랫폼)을 활용하되 통합 검증 이전에는 시험판 링크를 사용자 승인 대상으로 제시하지 않는다.
- GitHub `asea-college/asea` 지정 브랜치·커밋이 기준이고, 비파괴적 수정은 자동 커밋 및 검증한다.
- Supabase Free 유지. 신규 과금·영향이 큰 운영 삭제·RLS 완화·복구 불가 변경·기존 설치 서명 교체는 명시적 승인 필요.
- 1.0 정식 배포는 검증 결과가 뒷받침될 때만 명명하며, APK 파일이 생성되었다는 사실만으로 완료로 간주하지 않는다.
- 배포 상태는 '소스 구현', '정적 분석', 'CI 빌드', '서버 권한', '서로 다른 실제 계정 시험', '기기 설치', '운영 배포'로 구분해 보고한다.
- 사용자가 명시적으로 요청한 경우에만 운영 배포를 수행한다.
