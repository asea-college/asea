# 아세아 이음 0.2 — 오늘의 작은 이음 (마니또·소통문화) 상세 설계

기준일: 2026-10-31
기존 UX: 3번 시안(좌측 파란 메뉴, PC 메시지함, 모바일 하단 탭).
브랜드: 아세아 이음 · ASEA IEUM · 함께 이어가는 소통.
운영비: 기존 Supabase Free 유지. 외부 유료 서비스·호스팅 증설 전 별도 승인.

## UX 구성
- 소통센터 홈 → **오늘의 작은 이음** 카드
- 오늘의 마니또: 나만 볼 수 있는 상대방 이름/부서, 당일 미션, 완료 표시, 참여 중지 설정
- 익명 감사 우체통: 대상 선택, 4~500자 응원, 수신인에게 발송자 비공개, 하루 3건 한도
- 랜덤 커피 메이트: 다른 부서 매칭, 초대 거절과 10분 시간 조율(후속 클라이언트 구현)
- 선한 행동: 무료 인사·감사·도움·응원 카드; 선물 구매는 자율 선택
- 부서 간 이음 릴레이: 부서별 응원 메시지 제출; 공개 게시 및 순번은 후속 구현
- 이음 방송국 사연함: 사연 제출; 편집/검토 및 당사자 동의 후 방송할 수 있도록 설계
- 개인 참여 순위, 선물 구매 내역, 인사 평가 데이터 사용 없음

## 서버 정책
- 매일 새로운 상대를 배정. 원칙적으로 다른 부서 직원 우선; 대상이 부족하면 같은 부서.
- 전체 승인된 교직원은 기본 참여(아직 참여 설정이 없는 계정도 포함); 옵트아웃은 본인만 변경 가능.
- 본인 배정 정보 조회는 `notice_kindness_my_status` (본인의 대상자·미션만 노출).
- 발송자 익명성: 수신함 `notice_kindness_inbox`는 body/created_at만 반환, sender_id 비노출.
- DB 운영·보안 조사 목적으로 발송자 내부 감사 기록은 보존. '완전 추적 불가' 익명 아님.
- 관리자 수동 배정 `notice_kindness_dispatch`는 당일/평일/최고 관리자 인증만 허용; 동일 직원 하루 중복 배정 방지.
- 옵트아웃 `notice_kindness_opt`, 완료 `notice_kindness_complete`, 감사/사연 `notice_kindness_send`.
- 익명 감사 메시지는 참여자가 아니더라도 접근 제한된 수신자에게 전송할 수 있으며, 선물 지급과는 분리.
- 관리자에게 다른 직원의 마니또 상대방을 보여 주는 UI 없음.
- 메시지 본문 및 민원 신고 처리를 위한 관리자 검토, 차단·신고 기능은 다음 단계.

## 시간·알림 정책
- 목표: **평일 오전 9시 KST 미션 푸시**, 저녁 개인 완료 확인 알림.
- 날짜는 KST 기준, 서버 타임스탬프는 UTC.
- 현재는 관리자 수동 당일 배정과 앱 내 조회까지 구현. 9시 자동 스케줄러·FCM/APNs 발송·저녁 알림 **미구현**.
- 야간 수면 방해가 없도록 수신자에게 당일 마니또 발송자의 신원이나 활동을 알려주지 않음.
- 알림 수신 거부 가능해야 하고 참여 거부와 일반 공지 알림 거부는 분리.

## 설치·배포 상태
- Web: `apps/portal/kindness.html` + `community.html` 링크. 운영 호스팅 미배포.
- Android/iOS: Flutter `apps/mobile/lib/kindness.dart` 화면. APK/IPA 이번 버전 빌드·실기기 검증 별도 필요.
- Windows: 기존 앱을 유지하며 마니또 UI는 후속 통합 작업.
- 새 DB 마이그레이션: `server/migrations/20261031_notice_kindness_community.sql`. 기존 기록 삭제 없음.
- 주의: 라디오 방송 사연/릴레이 사연은 안전한 검토·게시 UI 구축 전까지 제출 형태로만 이용.

## 우선 검증
1. 직원 A/B/C: 같은 부서·다른 부서 우선 배정, 본인 배정만 조회, 비참여 제외, 하루 중복 방지.
2. 수신자 응원 수신함: 발송자 식별 정보가 DB 결과·네트워크 응답에 포함되지 않는지 확인.
3. 미승인 사용자·직원 간 계정 격리·타인 완료 조작·푸시 토큰 접근 차단 확인.
4. 평일/주말·KST 9시/18시·데이터 보존 및 옵트아웃 변경 시점 검증.
5. APK 최신 빌드, iOS 서명, 무료 운영 한도 및 음악/사연 저작권 검토.
