# 아세아 이음 — 자율 개발·수정·자동 검증·배포 운영 지침 (2026-10-31)

적용 범위: `asea-college/asea`, `feat/notice-foundation`, PC·웹·Android·iOS·Supabase.
이 문서는 기존 프로젝트 지침에 **추가**되며, 승인 없이 안전하게 처리할 수 있는 항목의 자동화 수준을 높인다.

## 기본 원칙: 사용자가 목표를 제시하면 중단 없이 완료까지
1. 최신 GitHub 저장소·브랜치·기준 커밋 확인. 추정 소스 사용 금지.
2. 발생한 오류를 재현하고 로그·원인·영향 범위를 확인. 필요한 경우 공식 기술 문서 참고.
3. 기존 동작·데이터 보존을 최우선으로 최소 변경.
4. 코드 및 회귀 검증과 보안 검증. 오류 시 수정→재빌드→재검증을 반복.
5. 별도 승인이 필요 없는 개발용 브랜치의 변경 사항은 자동 커밋·푸시, Draft PR 및 CI로 자동 검증.
6. 검증된 시험판 아티팩트를 자동 생성하고 다운로드 방법 제공. 직접 링크는 **실제 파일을 다운로드·추출·검사한 후** 제공.
7. 완료 보고: 대상 앱, 변경 파일, 기준 커밋, DB 마이그레이션, 검증 결과, 배포 상태, 버전, 알려진 오류.

## 승인 없이 자동 실행할 수 있는 작업
- 화면 디자인·내비게이션, 오류 메시지·입력 검증·복구 안내, 권한을 강화하는 비파괴적 코드 수정
- 테스트 추가, CI 수정, 의존성 버그 수정, Git 브랜치 커밋/푸시, Draft PR 갱신
- 개발·시험 환경의 비파괴적 마이그레이션, RLS 강화, API 및 사용자 경험 개선
- 기존 무료 범위의 Android 디버그 시험판 자동 빌드 및 아티팩트 업로드
- 기존 경로의 비파괴적 시험판 배포. GitHub Release 등 외부 게시 범위는 공개 여부·서명 체계가 확정된 이후 사용
- 이미 명시적으로 사용자가 요청한 범위 내의 운영 배포는 검증과 롤백 절차가 갖춰진 경우 수행

## 반드시 승인·확인이 필요한 작업
- 신규 비용, 유료 API·호스팅 플랜, Apple Developer 결제, 추가 과금
- 운영 DB 데이터 삭제·초기화, RLS 완화, 다수 사용자 권한 변경, 비밀값 교체, 로그인 우회
- 되돌리기 어려운 운영 배포·스키마 비호환 변경·기존 앱 서명/식별자/앱ID 전환
- 자동으로 사용자를 대신한 비밀번호 변경이나 인증 우회. 사용자는 비밀번호·인증 링크를 공개 채팅에 보내지 않음
- 실제 사용자 전체에게 테스트성 대량 푸시/이메일 발송

## 설치형 앱의 연속 업데이트 원칙
- Android `applicationId` 고정 및 안정적인 서명 키를 GitHub Secrets 등 보호된 저장소로 관리
- CI 실행마다 다른 debug 서명으로 빌드한 APK는 **덮어쓰기 업데이트 불가**할 수 있음
- 현 `kr.ac.asea.ieum.beta`는 독립된 시험판 ID. 서명 체계를 확정하기 전엔 지속 업데이트 보장 불가
- `versionCode` 증가, `versionName`/파일명 통일, APK 자체 manifest 및 인증서 검사 후 다운로드 링크 제시
- iOS는 macOS/Xcode/Apple 서명 조건과 비용 승인 상태를 검토하고 가능한 범위에서 먼저 검증
- Windows AppId·업데이트 경로, 웹 캐시·롤백 절차 유지

## 인증 및 최고 관리자 UX 복구
- `Invalid login credentials (400)`: 이메일/비밀번호 불일치 또는 인증 구성 문제. 최고 관리자 `role`과는 구분
- Supabase `notice_profiles`는 **로그인 성공 후** status/role 확인
- 사용자에게는 한국어 오류 안내, 안전한 비밀번호 재설정 요청 버튼 제공
- 로그인 성공 및 role=super인 경우 상단 **관리자** 텍스트 버튼 표시
- 관리자 기능은 서버 RPC / RLS에서 권한 재검증; 클라이언트의 이메일 문자열 비교·고정 비밀번호 금지
- 재설정 메일 링크의 redirect/복구 완료 화면은 별도 E2E 검증 전까지 완성으로 표현하지 않음
- 계정 자체의 인증 성공 여부는 사용자 인증 정보와 실제 인증 성공 응답 없이는 검증 완료라고 할 수 없음

## 속도 개선
- 독립적인 코드·테스트·기술 확인은 병렬 처리, 동일 파일의 순차 변경은 충돌 없이 수행
- 오류 발생 시 마지막 성공 버전으로 복원할 수 있도록 태그·아티팩트·마이그레이션 이력 기록
- 안전한 작은 변경 묶음으로 커밋하고 CI 오류 로그를 확인하여 즉시 재수정
- 실제 검증하지 않은 설치·로그인·운영 배포·자동 배포 완료를 주장하지 않음
- 사용자가 직접 설정·승인할 사항이 불가피하면 **필요한 최소 항목과 정확한 절차만** 요청
