# ASEA Notice — 교직원 통합 공지 시스템

## 목표
본 모듈은 ASEA 통합 업무 플랫폼의 공통 알림 기능으로 개발한다. 이후 `hr/`, `budget/` 등 모듈에서 같은 알림 및 확인 응답 서비스를 재사용한다.

## 확정 요구사항
- 관리자 웹앱 A2 카드형 / 공지 팝업 B1 카드형 / 일정 위젯 C1 목록형
- D3 블록 편집기 + 고급 자유 배치
- Pretendard Regular 및 학교 로고(밝은 배경 파란색, 파란 배경 흰색)
- Windows 7·10·11 지원 검토, 최초 설치 후 사용자 로그인 시 자동 실행
- 교직원 가입(이름, 부서, 아이디, 비밀번호), 부서 승인, 관리자 비밀번호 재설정
- 다중 PC 로그인·로그아웃·계정 전환, 트레이 아이콘
- 전체/부서/개인 대상, 즉시/예약 공지, 확인·동의·의견·문항 응답
- 공지 응답 서버 저장 확인, 오프라인 암호화 대기열, 재연결 시 중복 방지
- 응답 이력 1년 기본 보관, 변경 이력 추적 및 최소 권한 정책
- 기존 일정 시스템 `https://bangdw-hash.github.io/asea-calendar-management/schedule.html`의 디자인 및 운영 데이터 변경 금지. 일정 등록/수정은 원칙적으로 기존 사이트에서 처리.
- 배포용 자동 업데이트는 서명 검증과 구버전 호환성 검증 필수.

## 저장소 책임 분리
- `notice/`: 공지 전용 도메인 규칙, 발송, 응답, 템플릿
- `apps/`: 관리자 웹앱 및 Windows 통합 클라이언트
- `shared/`: 공통 계정, 부서, 권한, UI 디자인 토큰
- `server/`: 데이터베이스 마이그레이션, 인증된 서버 API
- `docs/`: 아키텍처, 검증/배포/운영 문서

## 개발 우선순위
1. 별도 개발/시험용 Supabase 프로젝트 준비 및 인증/RLS 마이그레이션 구현
2. 관리자 웹앱 및 공지 응답 워크플로와 디자인 편집기 구현
3. Windows 앱·트레이·자동 실행·오프라인 큐 구현
4. 기존 캘린더와 권한을 고려한 읽기 연동 및 웹 편집 바로가기
5. 자동 업데이트·설치 파일·Windows 버전별 실기기 검증

## 안전 규칙
기존 `asea-workspace` 운영 DB 및 `bangdw-hash/asea-calendar-management` 운영 저장소에는 명시적 승인 전 마이그레이션/파괴적 변경을 가하지 않는다. 새 개발용 DB가 확인될 때까지 SQL은 버전 관리만 한다. 모든 RLS는 서버의 실제 사용자 식별자를 기준으로 한다. 비밀키는 앱과 GitHub에 커밋하지 않는다.

## 상태
초기 개발 단계. 이 파일은 기능의 구현·배포 완료를 의미하지 않는다.
